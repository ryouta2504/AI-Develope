AI チームとシステムのデータフロー

PM（メインセッション）が部下のサブエージェントに 1 タスクずつ指示を出し、成果物はフックの検査を通ってから書き込まれます。合否はスクリプトが判定し、状態は .ai-dev/ に一元化されます。人間は 4 つの承認（G0〜G3）とマージ、そしてテンプレート自体を変えるときのメンテナンスの切り替えだけを担います。フックの列挙で止められない書き込みは、tripwire が結果で検出して元に戻します。出力の精度は Y = F(x) で考え、役割に合うモデル（F）を選び、必要なファイルだけ（x）を渡します。

ノードを選ぶと、その役割の入出力が表示されます

PM（AI リーダー）

メインセッション · 計画・委任・進捗管理

1 サイクルの流れ

cycle/C-001-xxx ブランチ = 1 PR

  1. 計画: PM が手法・ロードマップ・バックログを作成 G0 人間
  2. 要求: requirements が書き、reviewer 2 観点がコールドレビュー（RV-01） REQ_REVIEW G1 人間
  3. 設計: architect が DES と WP 表を書き、reviewer 3 観点（RV-02） DESIGN_REVIEW G2 人間
  4. テスト: test-designer が WP ごとに並列で失敗するテストを書き、reviewer 2 観点がテストをレビュー（RV-03） RED → テストをロック（誤りは reopen で解除）
  5. 実装: implementer が WP ごとに worktree で並列 TDD（WP の GREEN は担当テストと lint）、直列にマージ GREEN
  6. レビュー: reviewer 4 観点が並列に、経緯を知らない状態でレビュー（RV-05） CODE_REVIEW
  7. PR: PM が PR を作成、CI がハッシュ・承認・実施記録を再検証 G3 人間 → CI 再実行 → 人間がマージ
  8. 振り返り: /retro で改善候補（improvements）を残し、台帳の負債が溜まれば /refactor を人間に提案

テンプレート自体の変更

feature/* ブランチ = メンテナンス中だけ

  1. メンテナンス: 人間が npm run maintenance -- on（時間制限つき。AI は実行できない） 人間
  2. 変更: PM がテンプレート（.claude・scripts・基準文書など）を変更。tripwire はこの間だけ変更を受け入れる
  3. 相互レビュー: reviewer 4 観点（ガードの抜け穴・ロジックの正しさ・ドキュメントとの整合・保守性）が最終版をレビュー（RV-PF） PLATFORM_REVIEW
  4. 解除と PR: 人間が maintenance -- off、feature/* の PR。CI が RV-PF を照合し、コードオーナーがレビュー 人間

保護の層

列挙で止め、結果で検出し、最後は人間

  1. Hooks: フェーズ・役割・所有パス・テストロックで、書き込みやコマンドを事前に止める（列挙のため網羅はできない）
  2. tripwire: 手段を問わず、テンプレートと承認記録（G0〜G3）の変更を結果で検出して戻す
  3. CI: ハッシュ・承認・実施記録・テストを再検証。cycle・plan・feature 以外のブランチは不合格
  4. 人間: コードオーナーのレビューと PR の確認。承認コミットへの署名は将来の課題（既知の限界）
