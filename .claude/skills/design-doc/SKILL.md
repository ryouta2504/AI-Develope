# 設計書の書き方

## 設計要素（DES）
| ID | 名称 | 対応要求 | 概要 |
|---|---|---|---|
| DES-001 | タスク追加フォーム | REQ-001, NFR-001 | |

- 表の 1 列目に DES の ID、同じ行に対応する REQ / NFR の ID を書く（自動で紐づけを検証する）
- すべての Must 要求に 1 つ以上の DES が必要
- 要求の文章をコピーしない（ID で参照する）

## 作業パッケージ（WP）表
| WP | 名称 | 所有パス | 依存 | 設計 |
|---|---|---|---|---|
| WP-00 | 共通基盤 | src/shared/**, src/App.tsx | - | DES-001 |
| WP-01 | タスク追加 | src/features/add/** | WP-00 | DES-002 |

- **所有パス**: その WP だけが変更できるパス（glob、カンマ区切り）。WP ブランチ上ではフックが所有パス外への書き込みを止める
- 所有パスは WP 間で重ねない。共有するファイル（型・ルーティング・App.tsx など）は WP-00 に入れ、最初に直列で実装する
- **依存**: 先にマージされている必要がある WP
- 1 つの WP は、1 人の implementer が 1 タスクで終えられる大きさにする（テスト 10 件以下が目安）

## 推奨ディレクトリ構成（React）
```
src/
  shared/           型・共通コンポーネント・ユーティリティ（WP-00）
  features/<機能>/   機能ごとのコンポーネント・フック・テスト
  App.tsx, main.tsx
e2e/                Playwright
```

## 技術選定
- 選んだもの・理由・検討した代替案・採用しなかった理由を書く
- 新しい依存パッケージは、必要性とメンテナンス状況を書く
