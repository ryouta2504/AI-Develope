---
description: 技術的負債の台帳から、リファクタリング専用サイクルを始める
---

1. `npm run debt` で未解消の負債を確認する（重大度の高いもの・同じ場所のものをまとめて 1 サイクルの対象にする。広げすぎない）
2. 計画（docs/plan.md）のバックログにリファクタリングが入っていなければ、人間に提案する（変更すると G0 の再承認が必要）
3. `npm run cycle:new -- --refactor --debt DEBT-001[,DEBT-002] <短い名前>` でサイクルを開始する（要求定義はリファクタリング用のテンプレートになる）
4. 通常のサイクルと同じゲートを通す。違いは次のとおり:
   - 振る舞いは変えない。機能追加・変更はしない
   - RED は「既存のテストがすべて成功している」ことを確認してロックする（失敗するテストは要らない。足りなければ先に特性テストを追加する）
   - GREEN 以降はテストを書き換えられない。構造だけを変える
   - CODE_REVIEW の前に、PM が docs/debt.md の対象の負債を「解消」にし、解消サイクルにこのサイクル ID を書く
